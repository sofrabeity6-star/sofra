# تطبيق سفرة للموبايل (Expo)

تطبيق العميل لأندرويد وآيفون (وللويب أيضاً) بـ **Expo SDK 57 / React Native**، يتصل بنفس خادم سفرة. يعمل مباشرة في **Expo Go** بدون أي بناء.

## لوحة الإدارة الكاملة من نفس التطبيق

اضغط **«دخول الإدارة»** في شاشة الدخول وادخل بحساب المدير أو موظف المطبخ (المدير التجريبي `01000000000` / `admin12345`). تظهر لوحة الإدارة بدل شاشات العميل، وكل وظائفها متاحة على الموبايل والويب بنفس الكود:

| التبويب | المحتوى |
|---|---|
| **الطلبات** | مرتبة افتراضياً **بوقت التسليم من الأقرب للأبعد** (المتأخر بالأحمر، والفوري 🛵 أولاً)، والترتيب حسب **وقت التسليم / وقت الطلب / سعر الطلب / المرحلة** مع **تصاعدي/تنازلي**، وفلاتر وبحث، وتفاصيل الطلب: اتصال وتأكيد المكالمة، مراجعة الإيصال، نقل المواعيد بين المراحل مع إقرار الكاش، الإلغاء والاسترداد |
| **المطبخ** | أجندة اليوم بالكميات المطلوبة وخروج كل ساعة، وزر «ابدأ تجهيز كل وجبات اليوم» |
| **المنيو** | **المدير**: إضافة/تعديل/حذف الوجبات (الاسم، السعر، الوصف، **الصورة** من الكاميرا أو المعرض، متاحة/الأكثر طلباً/تصلح للفوري) وإدارة التصنيفات. **الموظف**: إيقاف/تشغيل الوجبة التي نفدت فقط |
| **المزيد** | **نظرة عامة** (المبيعات والنقدية والمتأخر ورسم آخر ١٤ يوماً)، **الإعدادات** (حسابات التحويل مع **كود QR** لكل حساب ورقم المطبخ، طرق الدفع، ساعات العمل والفاصل بين الأوقات، الرسوم، مدة الطلب الفوري، التجهيز التلقائي، إيقاف الطلبات مؤقتاً، والإعلان)، **الفريق والعملاء** (إضافة موظفين وتعطيلهم وقائمة العملاء) — للمدير |

وتصل الفريق إشعارات Push عند وصول طلب جديد أو إيصال تحويل أو إلغاء (في النسخة المنشورة، بنفس خطوات الإعداد أدناه).

## نسخة الويب من نفس التطبيق

نسخة الويب تُبنى في `mobile/dist` (تلقائياً على Render عند كل نشر، أو محلياً بـ `npm run build:web`) ويقدّمها الخادم على `/web/` (والجذر `/` يحوّل لها). لا يوجد غيرها: لا صفحات ويب منفصلة للعميل أو للإدارة. بعد أي تعديل في كود التطبيق أعد بناءها من المجلد الرئيسي: `npm run build:web`. للتطوير السريع على الويب: `npx expo start --web`.

## التشغيل على هاتفك بـ Expo Go (3 خطوات)

1. **شغّل الخادم** (من مجلد المشروع الرئيسي):
   ```bash
   npm run setup && npm run seed:demo && npm start     # يعمل على المنفذ 3000 (يقرأ .env)
   ```
2. **شغّل التطبيق** (في نافذة ثانية):
   ```bash
   cd mobile
   npm install
   npx expo start
   ```
3. **افتحه على الهاتف**: ثبّت تطبيق **Expo Go** من المتجر، ثم امسح الـQR: بكاميرا الآيفون، أو من داخل Expo Go على أندرويد. **يجب أن يكون الهاتف والكمبيوتر على نفس شبكة الواي فاي.**

التطبيق **يستنتج عنوان الخادم تلقائياً** من عنوان جهاز الكمبيوتر (نفس عنوان Expo، المنفذ 3000)، فلا تحتاج لضبط شيء. إن لم يتصل: من شاشة الدخول ← «إعدادات الخادم» اكتب `http://عنوان-الكمبيوتر:3000`. تأكد أن جدار الحماية يسمح بالمنفذ 3000.

**الويب**: `npx expo start --web` للتطوير، أو `npm run build:web` من المجلد الرئيسي للنسخة التي يقدّمها الخادم.

## للإنتاج

- ضع عنوان خادمك الحقيقي (**HTTPS إلزامي** في نسخ المتاجر): `EXPO_PUBLIC_API_URL=https://sofra.onrender.com` (رابط خدمتك على Render) في `mobile/.env` (انظر `.env.example`).
- أضف أيقونة التطبيق وشاشة البداية في `app.json` (`icon`, `splash`) قبل النشر على المتاجر.
- البناء والنشر على App Store / Google Play عبر **EAS**: `npm i -g eas-cli && eas build -p android` (و`-p ios`) ويتطلب حساب Expo (وحساب Apple Developer للآيفون).
- على الخادم: اضبط `CORS_ORIGINS` فقط إذا استضفت نسخة الويب من التطبيق على نطاق مختلف (التطبيقات الأصلية لا تحتاج CORS).

## إشعارات الهاتف (Push) بعد النشر

مفعّلة في الكود بالكامل (الخادم + التطبيق): عند كل تغيّر في حالة الطلب (تأكيد، بدء التجهيز، خرج للتوصيل، تم التسليم، رفض إيصال، استرداد...) يصل العميل إشعار على هاتفه حتى لو التطبيق مغلق، وبالضغط عليه يفتح الطلب نفسه. **لا تعمل داخل Expo Go**، فيتخطاها التطبيق بهدوء. تعمل في نسخة منشورة أو Development Build. الخطوات لمرة واحدة:

1. `npm i -g eas-cli` ثم `eas login` ثم داخل `mobile/`: **`eas init`** (ينشئ مشروعاً ويكتب `extra.eas.projectId` في `app.json` تلقائياً؛ بدونه لا يُنشأ توكن الإشعارات).
2. **أندرويد** (FCM): أنشئ مشروعاً في Firebase، وأضف تطبيق أندرويد بالحزمة `com.sofra.app`، ونزّل `google-services.json` وضعه في `mobile/` وأضف في `app.json` تحت `android`: `"googleServicesFile": "./google-services.json"`. ثم ارفع **مفتاح FCM V1 (Service Account)** إلى EAS: `eas credentials` ← Android ← Push Notifications (FCM V1).
3. **آيفون** (APNs): يلزم حساب Apple Developer؛ عند `eas build -p ios` يعرض عليك EAS إنشاء مفتاح الإشعارات (APNs Key) وإدارته تلقائياً.
4. ابنِ ونزّل: `eas build -p android --profile production` (و`-p ios`)، أو للتجربة على هاتفك قبل المتاجر: `eas build -p android --profile preview` (ملف APK تثبّته مباشرة).
5. **اختبر**: سجّل دخول من التطبيق المنشور، وأكّد طلباً من لوحة الإدارة، فيصلك الإشعار. أو أرسل إشعار تجربة يدوياً من https://expo.dev/notifications بالتوكن المسجل في جدول `push_tokens`.

على الخادم (الإنتاج): يجب أن يصل للإنترنت ليتصل بخدمة Expo Push (`exp.host`). ضبط `EXPO_ACCESS_TOKEN` اختياري لتأمين الإرسال (من إعدادات حسابك في expo.dev ← Access Tokens ← Enhanced Push Security). فشل الإرسال لا يعطّل أي عملية، ويُحذف تلقائياً أي توكن لجهاز ألغى التثبيت.

## كيف يعمل

- **المصادقة**: رقم الموبايل + كلمة مرور، والتوكن محفوظ في التخزين الآمن للنظام (Keychain/Keystore).
- **المزايا**: تبويبان في أعلى المنيو: **«اطلب الآن»** (الافتراضي: طلب عادي يتجهز ويصلك فوراً) و**«جدولة طلب»** (تختار اليوم والساعة)، والسلة المجمّعة بالمواعيد، الدفع بتحويل (مع رفع الإيصال من المعرض أو الكاميرا) أو عند الاستلام، تتبع الطلب بمراحله، **التحويل من كاش إلى دفع مسبق** قبل مكالمة التأكيد، إلغاء الطلب أو موعد منفرد، تكرار الجدول، الإشعارات، العناوين المتعددة.
- **التحديثات**: لا يوجد SSE في React Native، فالتطبيق يستعلم كل 15 ثانية أثناء فتحه (وفور العودة إليه)، وتتحدث تفاصيل الطلب المفتوح كل 10 ثوانٍ.
- **الاتجاه العربي** مبني يدوياً ليظهر بنفس الشكل على أي جهاز بغض النظر عن لغة النظام.

## حدود معروفة

- **لم أشغّله على جهاز حقيقي**: تحققت منه بتجميع (bundle) ناجح لأندرويد وiOS والويب، وباختبار الشاشات كاملة بمحاكي React Native على الخادم الحقيقي. جرّبه على هاتفك قبل الاعتماد عليه، خصوصاً التقاط صورة الإيصال بالكاميرا.
- **إشعارات Push لم تُجرَّب على جهاز حقيقي**: الكود مكتمل ومُختبر بالمحاكاة (التسجيل، الإرسال، حذف التوكن غير الصالح، فتح الطلب بالضغط)، لكن لا يمكن تجربتها في Expo Go ولا في بيئتي. تحقق منها على أول نسخة `preview` تبنيها، واتبع خطوات FCM/APNs أعلاه بدقة.
- الأسماء العربية للأيام والشهور مدمجة في الكود (لا تعتمد على Intl)، أما المنطقة الزمنية فتعتمد على Intl في Hermes، وإن لم تُدعم يرجع التطبيق لتوقيت الجهاز.
