# سفرة / بيتي

منصة طلب وجبات مطبخ منزلي. **كود واحد** لكل شيء:

| الجزء | المكان | يعمل على |
|---|---|---|
| التطبيق (العميل + لوحة الإدارة في نفس التطبيق) | `mobile/` (Expo / React Native) | أندرويد + آيفون + الويب |
| الخادم (API + يقدّم نسخة الويب على `/web`) | `src/` (Node.js + Express) | Render |
| قاعدة البيانات + الصور | Supabase (Postgres + Storage) | سحابة |

- **العميل**: يطلب **الآن** (طلب عادي يتجهز ويصل فوراً، وهو الافتراضي) أو **يجدول** طلبه ليوم وساعة محددين، ويدفع بتحويل مع رفع الإيصال أو عند الاستلام بعد مكالمة تأكيد.
- **الإدارة** (من نفس التطبيق: «دخول الإدارة»): الطلبات بترتيب وقت التسليم، المكالمات، الإيصالات، المطبخ، المنيو، الإعدادات، الفريق، والتقارير.
- **الخادم**: Express + PostgreSQL (Supabase) + صور في Supabase Storage + إشعارات Push عبر Expo.

## التشغيل المحلي

المطلوب **Node.js 22.13 أو أحدث**، وملف `.env` في المجلد الرئيسي (انسخه من `.env.example` واملأ قيم Supabase).

```bash
npm run setup          # يثبّت الخادم والتطبيق مرة واحدة
npm run build:web      # يبني نسخة الويب من كود التطبيق
npm start              # ثم افتح  http://localhost:3000  (يحوّلك إلى /web/)
npm run seed:demo      # اختياري: منيو تجريبي إذا كانت قاعدة البيانات فارغة
```

- الجداول تُنشأ تلقائياً في Supabase عند أول تشغيل، ومساحات الصور (`sofra-menu`، `sofra-qr`، `sofra-receipts` الخاصة) كذلك.
- حساب المدير الأول يُنشأ من `ADMIN_PHONE` و`ADMIN_PASSWORD` عند أول تشغيل فقط.
- **على الهاتف (Expo Go)**: `npm run app` ثم امسح الـQR. التفاصيل والنشر على المتاجر والإشعارات في `mobile/README.md`.

```bash
npm test               # اختبارات الخادم (تحتاج Postgres محلي أو TEST_DATABASE_URL)
npm run test:app       # اختبارات التطبيق
```

> الاختبارات تعمل تلقائياً على GitHub مع كل push (`.github/workflows/ci.yml`) بقاعدة Postgres مؤقتة، ولا تلمس بيانات Supabase.

## النشر: GitHub ← Render ← Supabase

1. **GitHub**: كل push على الفرع الرئيسي ينشر تلقائياً على Render.
2. **Render**: New ← **Blueprint** ← اختر الريبو. يقرأ `render.yaml` وينشئ خدمة `sofra` (منطقة Frankfurt، الأقرب لقاعدة Supabase). أدخل القيم المطلوبة من ملف `.env`:
   `DATABASE_URL`، `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY`، `JWT_SECRET`، `CRON_SECRET`، `ADMIN_PHONE`، `ADMIN_PASSWORD` (و`EXPO_ACCESS_TOKEN` اختياري).
   البناء: `npm ci && npm run build` (يبني نسخة الويب من كود التطبيق)، والتشغيل: `npm start`، وفحص الصحة: `/healthz`.
3. **Supabase**: لا يحتاج إعداداً يدوياً. استخدم رابط **Transaction pooler** (المنفذ 6543) في `DATABASE_URL` لأن Render لا يدعم IPv6.
4. **إيقاظ الخادم المجاني**: خطة Render المجانية تنام بعد 15 دقيقة. أضف في GitHub ← Settings ← Secrets ← Actions: `SOFRA_URL` (رابط Render) و`CRON_SECRET`، فيستدعي `.github/workflows/cron.yml` الخادم كل 10 دقائق ويشغّل التجهيز التلقائي.
5. **تطبيق الموبايل**: ضع رابط Render في `mobile/.env` كـ `EXPO_PUBLIC_API_URL=https://...onrender.com` قبل بناء نسخ المتاجر بـ EAS.

**Docker** (بديل): `docker compose up -d --build` يبني الويب والخادم في صورة واحدة ويقرأ `.env`.

## أول خطوات المدير

1. «دخول الإدارة» ← **المزيد ← الإعدادات**: ضبط **حسابات التحويل (إنستاباي، فودافون كاش، بنك...) مع رفع كود QR لكل حساب** ليمسحه العميل ويحوّل مباشرة، و**رقم موبايل المطبخ** (يظهر للعملاء للاستفسارات). وفيها أيضاً كل ما يلي.
2. **المنيو**: أضف التصنيفات والوجبات. الوجبة التي تحتاج وقتاً طويلاً ألغِ عنها «تصلح للطلب الفوري» فتظهر للمجدول فقط.
3. **المزيد ← الفريق والعملاء**: أضف موظفي المطبخ (يرون الطلبات والمكالمات والإيصالات والمطبخ ويوقفون الوجبات، ولا يغيّرون المنيو أو الإعدادات).

## ما الذي يتحكم فيه المدير من الإعدادات (بدون تعديل كود)

- **حسابات التحويل + كود QR لكل حساب + رقم المطبخ**، وتفعيل/تعطيل **التحويل** و**الدفع عند الاستلام**.
- **الطلب الفوري**: تشغيله، **مدة التجهيز والتوصيل** (دقيقة)، ورسومه. ورسوم التوصيل للمجدول.
- **الجدولة**: ساعات العمل، **الفاصل بين الأوقات (15/30/60 دقيقة)**، أقل مهلة، أقصى مدة، والتجهيز التلقائي قبل الموعد.
- **إيقاف استقبال الطلبات مؤقتاً** مع رسالة للعملاء، و**إعلان** يظهر أعلى المنيو.
- أقصى عدد طلبات كاش معلقة للعميل، اسم المطبخ، والمنطقة الزمنية.

تصل التغييرات للعملاء خلال ثوانٍ بدون إعادة تشغيل.

## قواعد العمل (كلها مغطاة باختبارات)

| القاعدة | التفاصيل |
|---|---|
| الدفع المسبق | الطلب يبدأ «مراجعة الإيصال»؛ الأدمن يعتمد أو يرفض بسبب يصل للعميل، والعميل يعيد الرفع |
| الدفع عند الاستلام | يبدأ «بانتظار مكالمة التأكيد»؛ لا تجهيز قبل «تم التأكيد هاتفياً» (يُسجَّل الموظف والوقت والملاحظات) |
| التحويل من كاش لدفع مسبق | مسموح فقط قبل تأكيد الأدمن؛ محمي من التعارض اللحظي (الأول يفوز والثاني يتلقى رسالة واضحة) |
| الطلب العادي (الفوري) | **الافتراضي**: يتجهز ويصل بعد الآن + مدة قابلة للضبط (60 د)، برسوم توصيل مستقلة، للوجبات المعلّمة «تصلح للفوري» وضمن ساعات العمل؛ يبدأ تجهيزه فور التأكيد ويظهر بعلامة 🛵 |
| الطلب المجدول | تبويب «جدولة طلب»: يوم وساعة لكل وجبة (حتى 45 يوماً)، ويجمع وجبات الأسبوع أو الشهر في طلب واحد |
| مواعيد التسليم | لكل موعد حالته (مجدول ← قيد التجهيز ← في الطريق ← تم التسليم) |
| الإلغاء | يُمنع بعد بدء تجهيز الموعد؛ الموعد غير المجهَّز يُلغى منفرداً؛ المبالغ المحوَّلة تظهر «مستحقة للاسترداد» ويسجّل الأدمن ردّها |
| التجهيز | تلقائي قبل الموعد بمدة قابلة للضبط (3 ساعات، 0 = يدوي)، أو بزر «ابدأ تجهيز كل وجبات اليوم» |
| الكاش | عند «تم التسليم» لطلب كاش يُطلب إقرار باستلام المبلغ، ويدخل في تقرير النقدية |
| الحماية من الإساءة | حد أقصى لطلبات الكاش المعلّقة للعميل الواحد (3 افتراضياً) |
| إشعارات الهاتف | للعميل عند كل تغيّر في طلبه، وللفريق عند طلب جديد أو إيصال أو إلغاء (في النسخة المنشورة) |

**ترتيب الطلبات في الإدارة**: الافتراضي **وقت التسليم من الأقرب للأبعد** (المتأخر بالأحمر أولاً)، ويمكن الترتيب حسب **وقت الطلب** أو **سعر الطلب** أو **المرحلة**، وكلٌّ **تصاعدياً أو تنازلياً**، مع فلاتر النطاق والبحث.

## الأمان

- جداول Supabase مفعّل عليها RLS بدون سياسات: لا يقرأها أحد بمفتاح Supabase العام، والخادم وحده يصل لها.
- كلمات المرور بـ scrypt، وجلسات JWT (Bearer في التطبيق)، وجلسة الإدارة منفصلة عن جلسة العميل.
- التحقق من كل المدخلات (zod)، واستعلامات SQL مهيّأة، وقائمة بيضاء للترتيب، وحماية CSRF.
- صور الإيصالات خاصة (لصاحب الطلب والإدارة فقط) ويُتحقق أنها صور فعلية.
- الأسعار والتوفر من قاعدة البيانات عند إنشاء الطلب، ولقطة الأسعار محفوظة في الطلب.
- ترويسات أمان (Helmet + CSP صارم) وتحديد معدل لمحاولات الدخول.

## حدود معروفة

- خطة Render المجانية: أول فتح بعد النوم يأخذ ~50 ثانية (يقلّ مع cron الإيقاظ).
- الدخول برقم الموبايل + كلمة مرور (OTP يتطلب مزود SMS مدفوعاً). أرقام الموبايل المصرية فقط، والتوقيت الافتراضي `Africa/Cairo`.
- ساعات العمل داخل اليوم الواحد (لا تدعم الإغلاق بعد منتصف الليل).
- لا بوابة دفع إلكتروني: التحويل يدوي بإيصال.
- لم يُجرَّب التطبيق على أجهزة حقيقية ولا الإشعارات؛ اختُبر بتجميع ناجح للمنصات الثلاث وباختبارات تحاكي كل الرحلات على خادم حقيقي.

## هيكل المشروع

```
src/            الخادم: app.js (المسارات)، orders.js (منطق الطلبات)، db.js (Postgres والجداول)، storage.js (صور Supabase)، push.js
mobile/         التطبيق الوحيد (Expo): العميل + الإدارة، لأندرويد وآيفون والويب؛ mobile/dist = نسخة الويب المبنية (لا تُرفع على GitHub)
test/           اختبارات الخادم
scripts/        seed-demo.js
render.yaml     إعداد النشر على Render
.github/        اختبارات تلقائية + إيقاظ الخادم
```
